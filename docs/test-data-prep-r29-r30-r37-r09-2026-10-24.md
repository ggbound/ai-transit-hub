## 1. R29 — 过期 key → 401 `api_key_expired`（免费）

### 1.1 目标
验证过期 API key 被拒且错误码精确为 `api_key_expired`（区别于禁用 key 的 `invalid_api_key`）。

### 1.2 代码依据
- [auth.go](file:///Users/mac-yueyue0516/data/new_version/GitHub/ai-transit-hub/backend/internal/api/middleware/auth.go) L78-146：先查 `api_key = ? AND status = true`（不命中 → 401 `invalid_api_key`）；命中后查 `ExpiresAt`，已过期 → 401 `api_key_expired`（L130）。**明文 api_key 匹配，key_hash 不参与鉴权**。
- [user_api_key.go](file:///Users/mac-yueyue0516/data/new_version/GitHub/ai-transit-hub/backend/internal/models/user_api_key.go)：`ExpiresAt *time.Time`（nil=永不过期）、`Status bool` default true。
- 表约束：`api_key` UNIQUE NOT NULL、`key_hash` NOT NULL（鉴权不用，造数需填占位）。

### 1.3 造数（一条 SQL）
```sql
-- 前置查重（api_key 全局唯一）
SELECT id FROM user_api_keys WHERE api_key = 'sk_r29_expired_regression_0001';

INSERT INTO user_api_keys
  (user_id, key_name, api_key, key_hash, status, expires_at, created_at, updated_at)
VALUES
  (1, 'regression-expired-r29', 'sk_r29_expired_regression_0001',
   SHA2('sk_r29_expired_regression_0001', 256), 1, '2026-10-23 00:00:00', NOW(), NOW());
```

要点：
- `status=1` 且 `expires_at` 已过去（昨天）——若 status=0 会在第一步就变成 `invalid_api_key`，测不到过期分支。
- `key_hash` 填 SHA2 占位（NOT NULL 约束，鉴权不读）。
- 无需等待缓存过期：该 key 从未被请求过，认证缓存（30s TTL）中不存在。

### 1.4 执行与断言
```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer sk_r29_expired_regression_0001" \
  http://localhost:8080/v1/models
# 期望：401

curl -s -H "Authorization: Bearer sk_r29_expired_regression_0001" \
  http://localhost:8080/v1/models
# 期望 body：{"error":{"message":"...","type":"...","code":"api_key_expired"}}
```

断言（对齐套件 `err_envelope_ok` 风格）：
1. HTTP 401
2. `body["error"]["code"] == "api_key_expired"`

### 1.5 记账核对
401 发生在鉴权中间件，**不产生任何 usage_log / api_test_requests 记录**（网关层拦截零记录语义，与 R39 结论一致）。

### 1.6 清理回滚
```sql
DELETE FROM user_api_keys WHERE api_key = 'sk_r29_expired_regression_0001';
```

### 1.7 风险
无。不触碰现有 key；无计费。

## 2. R30 — 越权 record 查询 → 404 `record_not_found`（免费，零造数）

### 2.1 目标
B 账号 key 查询 A 账号（user_id=1）的 api_test_requests 记录 → 404 `record_not_found`（IDOR 防护）。

### 2.2 代码依据
- [videos.go](file:///Users/mac-yueyue0516/data/new_version/GitHub/ai-transit-hub/backend/internal/api/handlers/videos.go) L87-99：`GET /v1/videos/generations/tasks/{task_id}?record_id=X` 时，record 存在但 `apiTest.UserID != currentUser.ID` → 404 `record_not_found`。
- **关键细节**：record_id **不存在**时代码 fall through 到默认视频模型兜底（不会 404 record_not_found）——所以 record_id **必须用 A 账号真实存在的记录**。
- `task_id` 路径参数可任意：属主校验发生在任务查询之前。
- 现成数据：B 账号 key（user_api_keys.id=4，user_id=2，status=1，无过期）；A 账号回归轮已产生大量 api_test_requests 记录。

### 2.3 造数（零新增，两条查询定位现成数据）
```sql
-- ① 取 B 账号完整 key（现成 id=4）
SELECT api_key FROM user_api_keys WHERE id = 4 AND status = 1;

-- ② 取 A 账号一条真实记录 id（优先视频记录，Model 格式为 provider/model_code）
SELECT id, user_id, model, created_at FROM api_test_requests
WHERE user_id = 1 ORDER BY id DESC LIMIT 5;
```

### 2.4 执行与断言
```bash
B_KEY="sk_6mybmxwoo56kn..."   # 上一步 SELECT 的完整值
A_RECORD_ID=<②中任取一个>

curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer $B_KEY" \
  "http://localhost:8080/v1/videos/generations/tasks/task_dummy_r30?record_id=${A_RECORD_ID}"
# 期望：404

curl -s -H "Authorization: Bearer $B_KEY" \
  "http://localhost:8080/v1/videos/generations/tasks/task_dummy_r30?record_id=${A_RECORD_ID}"
# 期望 body：{"error":{"message":"Record not found","type":"invalid_request_error","param":"record_id","code":"record_not_found"}}
```

断言：
1. HTTP 404
2. `body["error"]["code"] == "record_not_found"`
3. `body["error"]["param"] == "record_id"`

### 2.5 记账核对
属主校验在上游调用前返回 404，**不产生任何记录**；A 账号的原记录不受影响。

### 2.6 清理回滚
无（纯查询，不写任何数据；B key 为现有数据，不动）。

### 2.7 风险
无。注意 B key（id=4）属现成测试数据，勿在其上做破坏性变更。

## 3. R37 — agent 创建 → 轮询 → completed + 资产下载（微计费，零造数）

### 3.1 目标
验证 `/v1/agent/tasks` 全链路：202 创建 → 轮询至 completed → 资产文件可下载（对应回归计划 T32/T33/T37）。

### 3.2 代码依据
- [agent_task.go](file:///Users/mac-yueyue0516/data/new_version/GitHub/ai-transit-hub/backend/internal/api/handlers/agent_task.go)：
  - L48-54 契约：`model`（必填，须 type=text 否则 400 `model_not_supported`）、`skills`（必填 min=1，SKILL.md frontmatter name，仅 enabled）、`input`（必填自由文本）、`max_iterations`（默认 8，上限 20）、`options`（可选透传）
  - L578-660 launchAgentTask：落库 pending → CreateInitialRecords（status=2）→ 异步 goroutine → 立即返回 **202** `{"task_id":"agt_...","status":"pending","poll_url":"/v1/agent/tasks/agt_..."}`
  - L715-742 loadSkillsByNames：`name IN ? AND enabled = true`，缺失 → 400 `skills_not_found`
  - L236-253 Show：`agentTaskDetailResponse = {AgentTask 全字段, steps:[...]}`；仅本人可见（他人 → 404 `task_not_found`）
  - L256-287 DownloadAsset：`GET /v1/agent/tasks/{taskId}/assets/{assetPath}`，路径如 `/note.md`（嵌套如 `/productions/hero/BRIEF.md`）
  - 生命周期：pending → running → **completed / partial**（循环耗尽但有资产）/ failed
- [agent_task.go models](file:///Users/mac-yueyue0516/data/new_version/GitHub/ai-transit-hub/backend/internal/models/agent_task.go) L8-44：`assets`（JSON，产出文件清单）、`result`、`iterations`、`steps`（工具调用 trace）。
- 配置（backend/.env 与 config.go L118-119）：
  - `SKILL_STORAGE_PATH` 未覆盖 → 默认 `./storage/skills`
  - `AGENT_TASK_STORAGE_PATH` 未覆盖 → 默认 `./storage/agent_tasks`
  - `AGENT_ALLOW_WORKSPACE_SCRIPT=true`、`AGENT_ROUTER_MODEL=doubao/doubao-seed-2-0-mini-260428`

### 3.3 造数（零新增）
现成数据全部满足：
- **技能**：选 `quick-note`（enabled=1，产出契约 `note.md` required=true，纯文本最轻量；poster-visual 会烧图片子调用、motion-clip 会烧视频子调用，成本高不选）
- **模型**：`doubao/doubao-seed-2-0-mini-260428`（type=text，32 模型清单中最便宜，function calling 支持）
- **前置检查**（执行时确认一次）：
```bash
ls -la backend/storage/skills backend/storage/agent_tasks   # 目录存在且可写
mysql ... -e "SELECT id, name, enabled FROM skills WHERE name='quick-note';"  # enabled=1
```

### 3.4 执行与断言
```bash
A_KEY="sk_hrIHgJC4i0ZW0..."   # user_id=1 现有回归 key

# ① 创建（202）
curl -s -X POST http://localhost:8080/v1/agent/tasks \
  -H "Authorization: Bearer $A_KEY" -H "Content-Type: application/json" \
  -d '{"model":"doubao/doubao-seed-2-0-mini-260428",
       "skills":["quick-note"],
       "input":"记录一条笔记：AI Transit Hub v1 兼容层 R37 回归验证通过，日期 2026-10-24",
       "max_iterations":4}'
# 期望：202 {"task_id":"agt_...","status":"pending","poll_url":"/v1/agent/tasks/agt_..."}

# ② 轮询（建议 ≤300s，间隔 5s；pending→running→终态）
curl -s -H "Authorization: Bearer $A_KEY" http://localhost:8080/v1/agent/tasks/{task_id}

# ③ 资产下载（assetPath 取轮询响应 assets 字段，quick-note 应为 note.md）
curl -s -H "Authorization: Bearer $A_KEY" \
  "http://localhost:8080/v1/agent/tasks/{task_id}/assets/note.md"
```

断言：
1. 创建：HTTP 202；`task_id` 以 `agt_` 开头；`status=="pending"`；`poll_url` 正确
2. 轮询终态：`status=="completed"`（若 `partial` 记录方言分诊：partial=循环耗尽但有资产，配合缺失明细断言）；`steps` 数组非空；`iterations >= 1`
3. 资产：`assets` 含 `note.md`（quick-note 产出契约）；下载 HTTP 200 且 body 非空、含笔记文本关键词
4. 记账：usage_log 出现 status=1 记录（cost = mini 模型多轮对话，~0.001 元级）；api_test_requests 有对应审计行

### 3.5 记账核对
- 创建即建 status=2 记录；RunTask 成功后 UpdateSuccessRecords（status=1 + tokens/cost）
- quick-note 无 image/video 子调用 → 无 billSubModelCalls 附加账
- 对账 SQL：
```sql
SELECT id, status, model, prompt_tokens, completion_tokens, cost, error_message
FROM usage_logs WHERE external_task_id = '{task_id}';
```

### 3.6 清理回滚
可选（建议保留审计记录）：
```sql
DELETE FROM agent_task_steps WHERE task_id = '{task_id}';
DELETE FROM agent_tasks      WHERE task_id = '{task_id}';
-- usage_logs / api_test_requests 按惯例保留（审计链）
```
```bash
rm -rf backend/storage/agent_tasks/{task_id}   # 工作区目录
```

### 3.7 风险
- **耗时**：Agent 循环分钟级（多轮 LLM 调用）→ 轮询上限 300s
- **partial 可能**：mini 模型若 function calling 不稳，可能循环耗尽 → partial（资产仍在，可下载）。断言双态预案：partial 时校验 `error_message` 含缺失说明 + 资产下载仍 200，标记分诊
- 失败时 usage_log status=0、cost=0（UpdateErrorRecords），零费用

## 4. R09 — content-only 视频创建（计费 ~¥5，放最后执行）

### 4.1 目标
验证 `content` 数组（豆包原生透传字段）单独使用时可创建视频任务，且网关零改动透传（P2 修复点 R08 prompt-only 的镜像用例）。

### 4.2 代码依据
- [videos.go](file:///Users/mac-yueyue0516/data/new_version/GitHub/ai-transit-hub/backend/internal/api/handlers/videos.go) L25-74：
  - body 一次 Unmarshal 到 map，**除 `model` 替换为 model.Code 外原样透传**（L33-38、L65）
  - 仅有的语义校验：prompt/content 互斥（L42-48，`prompt_content_conflict`）、prompt 须 string（L49-54）
  - content-only 不触发任何拦截 → 直达上游
- 对照基线：R08 prompt-only 请求 `{"model":"doubao/doubao-seedance-2-0-260128","prompt":"一只橘猫在草地上奔跑，阳光明媚，5 秒镜头"}`（scripts/regression_full_suite.py L641-652，实测 200 + ¥5.0094）
- 计费语义：创建即 CreateInitialRecords（status=2）；轮询至终态后 UPDATE status=1 + 实际 tokens/cost

### 4.3 造数（零新增，纯请求）
无 DB 造数。直接用 A 账号 key 发起请求。

### 4.4 执行与断言
```bash
A_KEY="sk_hrIHgJC4i0ZW0..."

# ① content-only 创建
curl -s -X POST http://localhost:8080/v1/videos/generations/tasks \
  -H "Authorization: Bearer $A_KEY" -H "Content-Type: application/json" \
  -d '{"model":"doubao/doubao-seedance-2-0-260128",
       "content":[{"type":"text","text":"一只白猫在雪地里追蝴蝶，阳光明媚，5 秒镜头"}]}'
# 期望：200，返回结构与 R08 一致（id、status 等顶层字段）

# ② 闭环轮询（与 R13/R12 相同节奏：立即查询 + 轮询至终态，≤360s）
curl -s -H "Authorization: Bearer $A_KEY" \
  "http://localhost:8080/v1/videos/generations/tasks/{id}?record_id={record_id}"
```

断言：
1. 创建：HTTP 200；返回 `id`（任务 ID）；**响应结构与 R08 prompt-only 完全同构**（网关不因 content 入参改变响应形状）
2. 立即查询：status 为进行中（queued/running/submitted）；无 content 键污染；顶层无 `video_url:null`（与 R13 断言一致）
3. 闭环：终态 completed 且产出视频 URL 可下载
4. 记账：usage_log status=1、cost 与 R08 同量级（seedance-2-0 ~¥5）；api_test_requests 对应行 Model 为 `provider/model_code`

### 4.5 记账核对
```sql
-- 创建后（status=2）
SELECT id, status, model, cost FROM usage_logs WHERE id > <基线> ;
-- 闭环后（status=1 + 实际费用）
SELECT id, status, tokens, cost FROM usage_logs WHERE external_task_id IS NOT NULL AND id > <基线>;
```

### 4.6 清理回滚
无（审计记录按惯例保留）。

### 4.7 风险与成本
- **成本 ~¥5**：R08 实测 prompt 含"5 秒镜头"仍生成 ~307s 视频（¥5.0094）——预算按 ¥5 计，时长提示不保证控费
- **上游 400 可能**：若 Ark 对 content-only 请求有额外约束（R36 已见 seedream 尺寸类约束的先例），网关会透传 400 信封——此时记录上游错误原文分诊（透传正确 ≠ 用例失败）
- 轮询不强制：仅创建成功即可验证 P2 透传点；但**建议轮询闭环**，否则 usage 记录悬在 status=2 无法完成计费对账
